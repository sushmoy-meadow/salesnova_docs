# TASK-TL-001 — open points

All four acceptance criteria have tests behind them. Seven of those tests only run on Postgres,
because privileges, partitioning and `TRUNCATE` do not exist on SQLite; CI runs the suite on both,
and the Postgres half was also run locally against a throwaway Postgres 16 before this closed.

---

## 1. Where the schema departs from the column table

`docs/04-domain-model.md` §10.2 gives the normative column list. Two departures:

- **`origin` is present and the column table does not list it.** The task description and
  `docs/features/F05-timeline-and-activity.md` §2 both require it, and it answers a different
  question from `actor_type`: how the fact arrived versus who caused it. An integration can post a
  fact whose actor is a lead.
- **`causation_id` is nullable.** The column table marks `actor_id` nullable and nothing else, but
  the first event in a chain has no cause. Null there is a fact, not a gap — and the criterion that
  requires non-null names `correlation_id` only.

`11-ai-substrate.md` §SN-AI-010 sketches the same table with `event_type` where the column table says
`event_name`. The column table won; the sketch is prose.

## 2. What this task deliberately does not build

- **Retention.** `SN-ARCH-021` enforces it by detaching old partitions. `TASK-INFRA-007` owns
  partition lifecycle and depends on this task. Nothing here drops or detaches anything, and the
  application role is proven unable to.
- **The writer.** `TASK-TL-004` is the append-only writer service and `TASK-AI-002` is the write/query
  API contract. The model exists and refuses updates and deletes; nothing in the tree appends
  through it yet, so no production code path is exercised end to end.
- **`timeline_event`.** The human-readable half is `TASK-TL-002`. The two must not be merged, which
  is why only one of them exists here.

## 3. What the guard covers, and the one thing it depends on

Immutability is a row trigger on the partitioned parent, which Postgres propagates to every
partition including ones created later. `TRUNCATE` is the exception: a row trigger never sees it, and
truncating a partition by name never reaches the parent's statement trigger — so both callers that
create a partition attach a truncate trigger to each name they get back. A partition created by hand
will accept a `TRUNCATE` that the parent would refuse.

The role separation test proves the trigger stops the statement. It does **not** prove the
application role lacks `UPDATE`/`DELETE` in the first place — that grant is made at the provisioning
layer and has no artifact in this repository. `TASK-HARDEN-014` provisions the database and is where
the second half of that guarantee lands.

## 3a. Two classes moved out of the domain

The append-only trigger DDL and the month-partition arithmetic were both written here first and both
turned out to be second copies of, or first copies of, something the backlog already commits to.
They now live in `App\Support\Database` as `AppendOnlyGuard` and `MonthlyPartitions`, parameterised
by table name:

- `AuditLogGuard` was a near-identical implementation of the same triggers and now delegates,
  keeping only the `audit_log` name, its refusal message and the suspend/restore pair that retention
  needs. Two copies of security-critical DDL is exactly the drift both docblocks existed to prevent.
- `SN-ARCH-021` specifies the same monthly partitioning for `timeline_event` and `whatsapp_message`,
  `TASK-TL-002` is next in this chain, and `TASK-INFRA-007` owns the job that covers all three. The
  generic form is not speculative here — the second and third callers are already named.

`TASK-INFRA-007` still has to fold the per-table command and config key into one job; this task left
`event:partitions` and `event_log.partition_months_ahead` event-specific rather than designing that
registry ahead of the task that owns it.

## 3b. The namespace segment is `Timeline`, not `Activity`

`docs/09-technical-architecture.md` puts `timeline_event`, `event` and `audit` in one module named
`Activity`. Nothing here uses that word: `audit` already shipped under `Security`, so the tree's
working convention is the domain of the task rather than the module of the spec, and this task is
`TL`. Recorded rather than silently taken, because `TASK-TL-002` creates `timeline_event` and will
land in the same namespace — the machine log holding the unqualified name `Event` beside a
`TimelineEvent` is confusable under any segment name, and that task should confirm or change the
pair together rather than inherit it.

## 4. `id` is not unique on its own

The primary key is `(organization_id, id, occurred_at)` — Postgres requires the partition column in
it, and this project requires the tenant to lead. The consequence is that the database does not
enforce global uniqueness of `id`. The ids are UUIDv7 generated by the application, so this is
theoretical, but a writer that supplies its own id gets no help from the database in rejecting a
repeat. Reasoning in `docs/adr/0025-event-log-partitions-and-identity.md`.
